# dsh-archive-session-manager

DSH（DeepSeek Harness）插件：管理**已归档**会话 —— 删除、批量清理，以及修复会话归属。

DSH 平台本身没有「删除会话」的入口，归档会话只能一直留着。本插件补上这个能力，并提供几项随附的维护工具。

## 功能

- **删除单个归档会话**：会话「···」菜单里，已归档的会话多出一项「删除会话」（带确认对话框，永久删除磁盘记录）。
- **归档会话管理页**（设置 → 归档会话）：列出全部归档会话（标题 / 时间 / 目录 / 磁盘占用），支持**多选、全选、批量删除、批量取消归档**与刷新。
- **归位失效会话**：把「磁盘上有、但不在任何工作区记账里」的会话（它们会显示在侧栏的「未分组」）重新挂回其工作目录对应的工作区。只修归属，不删文件；子智能体会被自动跳过。
- **一键摘除误记账的子智能体**：子智能体不该占用用户工作区的归属槽位。若历史版本把子智能体挂进了记账，可一键摘除 —— 只改记账、不动磁盘。
- **清理遗留空会话**：找出「建了但从未有过对话」的历史会话目录并永久删除。**这是唯一按内容判据批量删文件的功能**，因此走两步确认，且宿主会二次校验（任何有对话内容的会话一律拒删）。
- **清理幽灵记账**：清掉「记账里还记着、磁盘上已不存在」的失效条目。

入口放在设置页而非侧栏：这是低频的批量维护操作，不是会话内的日常动作。

## 安装

```sh
dsh plugin --profile web add github:felixpu/dsh-archive-session-manager
```

⚠️ 安装或升级后**需要重启 DSH**：宿主半身与客户端 bundle 都在进程启动时装载，不重启不会生效。

## 使用

### 删除一个归档会话

1. 先归档它（平台自带的「归档」菜单项）；
2. 在会话「···」菜单里选「删除会话」；
3. 在确认对话框里确认。

⚠️ 删除不可恢复。

### 归档会话管理页

**设置 → 归档会话**。勾选若干行后可批量删除或批量取消归档，右侧有刷新。页面会按实际情况显示各项维护入口。

### 维护项一览

| 入口 | 作用 | 是否动磁盘文件 |
|---|---|---|
| 归位失效会话 | 把未记账的会话挂回其工作目录对应的工作区（消掉侧栏「未分组」） | 否 |
| 摘除误记账的子智能体 | 把子智能体从工作区归属记账里摘掉 | 否 |
| 清理幽灵记账 | 清掉磁盘上已不存在的记账条目 | 否 |
| 清理遗留空会话 | 删除「从未有过对话」的空会话目录 | **是** |

除最后一项外都只改记账，且都先给只读预览再执行。

## 安全边界（设计决定）

- **只有已归档的会话可以删除**。未归档会话没有删除入口；直接调接口也会被逐条拒绝（`not-archived`）。归档本身就是平台表达「确认不再使用」的动作，插件不另造一套确认语义。
- 只有**正在执行任务**的会话拒绝删除；被打开过但处于空闲的会话允许删除 —— 它只是常驻内存，并没有进行中的写入。
- 会话目录路径严格限制在 `$DSH_HOME/sessions/` 之下并做前缀校验，拒绝任何越界。
- **删除不可恢复**。需要备份时请自行复制 `~/.dsh/sessions/` 下对应目录。
- 空会话清理在服务端**重算判据**，不信任前端传来的 id：有对话内容的一律拒删。

## 设计要点

### 「删除」为什么是一组动作

DSH 平台**没有**会话级删除 API：`sessionPersistence` 只有 `create` / `open` / `flush` / `stat` / `list`，`sessionController` 与 `workspaceRegistry` 也都没有删除会话的方法（后者的 `delete` 删的是**工作区**）。

所以本插件的「删除」由四步组成：

1. **驱逐内存态** —— 让平台真正忘掉这个会话；
2. 删除磁盘目录；
3. 从归档集合移除；
4. 从工作区记账摘除。

顺序有讲究：必须**先驱逐、再删目录**。会话收尾时会做最后一次落盘，而落盘会重新创建目录 —— 顺序反了，刚删掉的目录会被建回来。

### 被打开过的会话为什么需要特殊处理

在浏览器里打开过的会话会常驻在宿主进程内存里，并被**两条内存通路**持续列出来。此时只删磁盘文件没有用：刷新后它照样会出现。

本插件会先把它从平台内存里**驱逐**出去（上一条的第 1 步），再删磁盘与记账 —— 正常情况删除**当场生效**。

如果某次驱逐被平台拒绝，该条目会以「待重启」的形式单列在管理页，并提供一个**「重试驱逐」**按钮：

- 它**不会**出现在侧栏，也不会混进归档会话列表；
- 点「重试驱逐」即可当场清掉；重启 DSH 也会自动收敛。

### 侧栏里的「未分组」是什么

会话只要不在任何工作区的记账里，就会落进侧栏的「未分组」分组。常见来源有两个：

1. **删除了一个曾被打开的归档会话** —— 归属被摘掉、但会话仍留在内存里，于是变成「没有归属的会话」。本插件删除时会先驱逐内存态，因此不会再产生这种情况；若你曾用早期版本删过，可能已经留下这类条目。
2. **历史遗留的未记账会话** —— 从未被挂进任何工作区。

两种情况都用管理页的「**归位失效会话**」处理：把这类会话挂回其工作目录对应的工作区，「未分组」随之消失。归位会跳过子智能体 —— 它们本就不作为列表行显示，塞进工作区记账属于脏数据。

## 常见问题

**删除了，但列表里还有它？**
先刷新页面。若管理页出现「待重启」条目，那是驱逐被平台拒绝时的兜底，点「重试驱逐」即可；再不行重启 DSH。

**侧栏出现「未分组」了，是删除造成的吗？**
见上文「侧栏里的『未分组』是什么」。用「归位失效会话」把它们挂回工作区即可。

**为什么「删除会话」只出现在已归档的会话上？**
归档是平台表达「确认不再使用」的动作，插件沿用这个语义、不另造确认流程。想删就先归档。

**删除会连带删掉子智能体吗？**
不会。子智能体有自己的会话记录，且不作为列表行显示。

**「清理遗留空会话」会误删我的会话吗？**
不会。判据是「日志里没有任何用户消息」，且在服务端重算、逐条二次校验；有任何对话内容的一律拒删。删除前也有只读预览。
